# 每日工作日报

把 `~/.claude/projects/**/*.jsonl` 里的一天，变成一份能直接看的日报。数据只在本地处理，不上传（除非归档驱动配置了云盘）。

## 安装结构

- 代码：本插件目录（`skills/`、`hooks/`、`scripts/`）
- 数据：`~/.daily-digest/`（`config.json`、`days/`、`state/`、`work/`、`current.md`、日志）
- 换机器：拷插件目录 + 拷 `~/.daily-digest/config.json`，其余由每日任务自己生成


## 触发与参数

| 输入 | 行为 |
|---|---|
| `/daily-digest` | 分析「昨天」（见下面的日界） |
| `/daily-digest 2026-11-04` | 分析指定日期 |
| `/daily-digest week` | 生成最近一周的周报 |
| 「总结一下今天」 | 当天还没结束，先说明会截断，仍按今天窗口跑 |

日期指**日界窗口的起始日**：`D 04:00 → D+1 04:00`（本地时间）。所以 11-05 早上 08:00 定时跑的是 `--date 2026-11-04`。

定时任务不再只看昨天：`run-daily.ps1` 按 `state/last-run.json` 从上次跑到的次日一路补到昨天（最多 14 天），0 会话的天跳过不调用模型，已有 `days/<date>.md` 的天跳过。手动 `/daily-digest <date>` 不受此限制。

## 流程

### 1. 抽取

```bash
python "${CLAUDE_PLUGIN_ROOT}/scripts/collect.py" --date <YYYY-MM-DD>
```

`CLAUDE_PLUGIN_ROOT` 为空时（例如在计划任务里），用 `D:\ClaudePlugins\daily-digest\scripts\collect.py`。

输出 `~/.daily-digest/work/day-<date>.json`（数据目录始终在用户主目录下，不随插件走）。

**如果该文件已存在且晚于当天 04:00，跳过这一步**——定时任务 `run-daily.ps1` 已经跑过抽取了，重复执行没有意义，而且无头模式下也能少一次命令。要点：

- `parse_failures > 0` 时在日报末尾注明，不要假装数据完整
- `diagnostics.excluded_projects` 里的项目是**统计保留、内容剔除**，不要尝试推断其内容
- `sessions` 里 `redacted: true` 的会话只能用于时间和数量统计

### 2. 分析

读 `day.json`，按下面的规则写日报。**只依据 day.json 里的内容**，不补充记忆里的推测；不足就写不足。

### 3. 写三个文件

| 文件 | 用途 | 长度 |
|---|---|---|
| `~/.daily-digest/days/<date>.md` | 完整日报 | 不限 |
| `~/.daily-digest/state/next.md` | 次日三个追问 | ≤ 500 字 |
| `~/.daily-digest/current.md` | 桌面小窗读的视图 | ≤ 900 字 |

### 4. 归档

**归档与清理一律由外层 `run-daily.ps1` / `run-weekly.ps1` 负责。本 skill 在任何运行方式下都不执行这两步**，包括交互式运行——重复归档会被目录策略拦下，还会把「归档失败」写进日报正文，误导读者。

如果日报里确实需要提一句存储状态，只写「已归档到本地」或留空，不要写失败原因。

| driver | 命令 |
|---|---|
| `local` | 复制 `days/<date>.md` 到 `local_path` |
| `rclone` | `rclone copy <file> <remote:路径>` |
| `baidu` | `bdpan upload <file> ClaudeDigest/<文件名>`（相对 /apps/bdpan/，别加前缀） |
| `notion` | 通过 Notion MCP 建页面 |
| `dingtalk` | `dws drive upload` |
| `shell` | 执行 `archive.command`，`{file}` 替换为文件路径 |

### 5. 清理

删掉 `days/` 里超过 `keep_local_days`（默认 7）天的日报，`work/` 超过 3 天的 `day-*.json`，`memo.log` 超过 1MB 时轮转。

## 分析规则

### 板块一：时间去哪了

用 `sessions[].blocks`（间隔超过 25 分钟自动切块）。每个块一行：时段、时长、在干什么、状态。

- 状态只有四种：`推进` / `卡住后止损` / `反复试错` / `收尾`
- 「在干什么」要落到具体对象，不写「做开发」
- 块之间的空档超过 90 分钟，在末尾补一句「中间 X:XX–X:XX 无活动」
- `redacted` 会话的块只写「已排除项目 · N 分钟」，**不要猜内容**

最后补三项统计：最长连续工作时长、有没有跨零点的会话、试错时长占比（`反复试错` 块合计 / 总活跃时长）。

### 板块二：今天做了什么

先用 `totals.by_project` 给一张项目时间表，再按「目标 → 过程 → 产出」组织内容，而不是按时间顺序复述。每个主题一段，不超过 150 字。

| 项目 | 时长 | 会话 |
|---|---|---|
| C--Windows-System32 | 3 小时 12 分 | 2 |

`redacted: true` 的会话按 `config.json` 的 `exclude_mode` 处理：

- `stats_only`：只有时间和数量，不能写内容
- `content_anonymous`：**有内容可写**（提问、文件、命令、结论句都在），但项目名一律用 `project_label`（已排除项目 · A/B/C），正文里也不要出现被遮蔽过的原文路径

**项目名只用 `project_label`，永远不要读或输出 `sessions[].project`** —— 后者是本地真实路径，仅用于 `day.json` 内部统计。`by_project[].key` 是项目名的稳定哈希，跨天对照同一个项目时用它。

- 有产出的必须点名产出物（文件、台账、部署、文档）
- 没做完的标 `未完成`，并写清卡在哪一步
- 结论只写 `excerpt` 里出现过的；`excerpt` 是截断的，不要声称覆盖了全天

### 板块三：提问质量

五个维度，每个维度只能给四种判断：**强 / 到位 / 有缺口 / 证据不足**。禁止打数字分。

| 维度 | 看什么 |
|---|---|
| 上下文 | 有没有给目标、环境、已有信息；问题里有没有可排查的线索 |
| 约束 | 有没有说明边界：环境性质、能不能停服务、什么人能用 |
| 验收 | 有没有定义「做成什么样算完成」，而不是「稳一点」 |
| 验证 | 遇到问题时有没有贴报错全文、有没有要求核对结果 |
| 纠错止损 | 卡住后多久换路子，有没有无限重试 |

每条判断**必须绑一句原话**（从 `prompts` / `excerpt` 里逐字引用，超过 40 字可截断加 `…`）。引不出来就写 `证据不足`，不许编。

最后一句总评，格式：`一句话：X 和 Y 做得好，Z 是这天的短板。`

### 板块四：次日三个追问

从三个来源各取一条，最多三条，每条必须是**明天能直接拿去问的问题**，不是感想：

1. 未完成事项 → 「这东西的完成标准是什么」
2. 反复试错的块 → 「下次先怎么复现」
3. 没验证过的结论 → 「怎么证明它真的成立」

写进 `state/next.md`。没有合格的问题就少写，不要凑数。

## 输出格式

### `days/<date>.md`

```markdown
# YYYY-MM-DD 工作日报

> 窗口：YYYY-MM-DD 04:00 → YYYY-MM-DD 04:00
> 会话：N 个 · 活跃 X 小时 Y 分 · 提问 N 条 · 报错 N 次
> 已排除：N 个会话（仅统计，无内容）

## 一、时间去哪了
（表格 + 三项统计）

## 二、今天做了什么
（主题段落）

## 三、提问质量
（表格：维度 / 判断 / 证据 + 一句总评）

## 四、明天先问自己
（1–3 条）
```

### `current.md`（小窗用，必须严格按这个结构）

```markdown
# 11月5日 周三

> 7 小时 16 分 · 4 件完成 · 3 条未完成

## 今天先问自己
1. 问题一
2. 问题二
3. 问题三
```

**只写这三块**：标题、摘要行（一天的总时长和完成情况）、三个追问。小窗自己会读 `tasks.md` 显示待办，所以这里不要写待办或「做了什么」的清单。

摘要行格式：`> X 小时 Y 分 · N 件完成 · M 条未完成`，数字取自日报统计，取不到就省略。

### 未完成事项写进待办

写 `current.md` 的同时，把日报里标 `未完成` 的条目追加到 `~/.daily-digest/tasks.md`：

- 格式：`- [ ] HH:mm <条目>`，时间取生成日报的时刻
- **先按文本去重**：`tasks.md` 里已有相同文字（无论完成与否）就跳过，不要重复追加
- 只追加未完成的，已完成的不动

### `state/next.md`

```markdown
# 次日追问（YYYY-MM-DD）

1. 问题
   - 为什么要问：一句话
   - 相关证据：原话或命令

2. ...
```

## 周报

`/daily-digest week` 或每周日 20:00 定时：

- 读 `days/` 里最近 7 天的日报，没有的跳过
- 输出 `~/.daily-digest/weekly/YYYY-Www.md`（单独目录）
- 结构：本周总时长 / 每天一条 / 重复出现的问题 / 下周三个方向
- 周报不重复日报细节，只做归纳

## 失败与降级

| 情况 | 处理 |
|---|---|
| 当天 0 会话 | 写一份「无记录」日报，`next.md` 保留昨日的，不覆盖 |
| `collect.py` 非零退出 | 报告错误原文，停止，不生成半成品 |
| 归档失败 | 记 `memo.log`，在日报末尾注明「归档失败：原因」 |
| 会话记录结构变更（parse_failures 高） | 停止分析并提示用户脚本可能需要更新 |

## 禁止事项

- 不为 `redacted` 会话编造任何内容
- 不把 `excerpt` 当全文，不写「全天都在…」这种覆盖性结论
- 不给提问质量打数字分
- 不在日报里出现配置中 `exclude_path_patterns` 命中的路径
- 不自动删除用户的会话记录（`.jsonl`）
