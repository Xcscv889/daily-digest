# 小臻长期记忆方案（P4）

> 目标：让记忆一直有用，但**每条消息的 token 和延迟恒定**，不随使用时间增长。

## 1. 基本原则

1. **写入不判断价值**。事实、时间、类型、来源之外不存任何“重要度预测”。
2. **价值由使用涌现**。被反复检索到的留在一线，冷门的沉到归档。
3. **原始对话永不直接进请求**。只以压缩后的一句话事实进入。
4. **只增不毁**。失效的、冷门的都保留，只有用户手动「忘记」才物理删除。
5. **每次请求有硬预算**，超了按固定顺序裁剪，不靠“大概控制”。

## 2. 资源预算（硬上限）

| 项目 | 上限 | 说明 |
|---|---|---|
| 人设 prompt | 260 字 | 固定 |
| 画像 profile | 400 字 | 常驻，你手写 |
| 检索到的记忆 | 3 条 × 50 字 | 本地 BM25 选出 |
| 最近对话 | 900 字 / 最多 8 轮 | 从最近往前装，装满即停 |
| 当前用户消息 | ~100 字 | — |
| **单次输入合计** | **≤1600 字**（约 1000–1100 token） | 超出按「记忆→旧对话」顺序裁剪 |
| 单次输出 | ≤800 token | — |
| 活跃记忆 | 500 条 | 超出移入 archive |
| 每日提取 | 最多补 2 天，每天 ≤6 条 | 启动时后台跑 |
| 每周合并 | ≤3 组 | 周日 |
| 检索耗时 | <2 ms（≤500 条） | 纯本地 BM25 |
| 常驻内存增量 | <1 MB | 500 条记忆 + 索引 |

## 3. 数据模型

```
~/.daily-digest/companion/
├─ profile.md          手写画像：城市、作息、喜恶、雷区（常驻 prompt，≤400 字）
├─ memories.jsonl      活跃记忆，一行一条，≤500 行
├─ archive.jsonl       归档记忆（满了移出来，不删）
└─ chat/yyyy-MM-dd.jsonl   原始对话（不直接进 prompt）
```

`memories.jsonl` 一行：

```json
{"id":"m20261120-3","ts":"2026-11-20","kind":"preference",
 "text":"喜欢冰美式，不加糖","uses":4,"last":"2026-12-02",
 "valid":1,"superseded_by":"","src":"2026-11-20","links":[]}
```

| 字段 | 含义 |
|---|---|
| `kind` | fact / preference / episode / boundary |
| `uses` / `last` | 被检索次数、最后一次被用到 —— **唯一的价值信号** |
| `valid` | 1 有效；0 已失效（被新事实取代），默认检索不到 |
| `superseded_by` | 指向取代它的新记忆，保留“以前是…”的能力 |
| `src` | 来自哪天的对话，可溯源 |
| `links` | 预留，v1 不用 |

没有 `weight`、没有 `importance` —— 这是本方案和常见做法最大的区别。

## 4. 写入路径（每天一次，后台）

### 4.1 触发

- 启动时检查：`chat/` 里日期 < 今天、且晚于 `mem_done` 的文件
- 每次最多补 2 天，避免长时间没开导致一次烧太多
- 每小时检查一次，空闲时执行；不做“每 N 条即时提取”

### 4.2 一次提取 = 一次 LLM 调用

输入：
- 当天对话，截到 4000 字
- 现有活跃记忆的编号 + 内容（最近 40 条）

输出格式（纯文本，一行一条，不走 JSON）：

```
ADD|preference|2|他喜欢冰美式，不加糖|
SUPERSEDE|fact|2|他在 2026-11 换了工作，去了新公司|m20261015-7
```

- `ADD`：新增
- `SUPERSEDE`：新事实取代旧记忆；旧条 `valid=0`、`superseded_by=新 id`，**不删除**
- 模型判断“以后还用得上”才输出；天气、寒暄、助手自己的话一律不记
- 没有可记的输出 `NONE`

### 4.3 本地后处理

1. **去重**：新事实与现有记忆的字二元组相似度 ≥0.75 直接丢弃
2. **落盘**：写 `memories.jsonl`
3. **归档**：活跃超过 500 条时，按 `新鲜度 + 使用次数` 淘汰最弱的 50 条 → 追加进 `archive.jsonl`
4. 记 `mem_done = 处理到的日期`

## 5. 读取路径（每条消息，本地）

### 5.1 组装顺序

```
人设（固定）
+ profile.md（≤400 字）
+ 检索到的 3 条记忆（每条 ≤50 字）
+ 最近 8 轮对话（≤900 字）
+ 当前消息
```

超出 1600 字时：先砍记忆到 1 条 → 再砍最旧的对话轮次。**当前消息和最近一轮永远保留。**

### 5.2 检索：BM25 + 客观信号

1. 把用户消息切成字二元组（中文）+ ASCII 词（英文）
2. 在有效记忆上算 BM25（k1=1.2，b=0.75）
3. 最终分：

```
score = BM25 + 0.8 × 新鲜度 + 0.05 × min(uses, 5)
新鲜度 = 0.5 ^ (距今天数 / 60)
```

4. 只保留 `BM25 > 0` 的，取前 3；命中的记忆 `uses++`、`last=今天`

没有向量、没有额外网络请求。查询少于 4 个字或纯表情时直接跳过检索。

### 5.3 可观测

每次请求写一行日志：

```
prompt: sys=1420 turns=780 mem=2 chars=2250
```

这是判断“有没有变慢”的唯一依据，也是以后调预算的输入。

## 6. 巩固（每周一次）

- 周日在后台跑，最多处理 3 组
- 分组：同 `kind` 且两两相似度 ≥0.5 的、≥3 条的簇
- 每组一次 LLM 调用，输出 1–2 条更概括的事实（保留具体名字/数字）
- 新条 `ADD`，组内旧条全部 `valid=0` 并指向新条
- 效果：条数下降、表述收敛，检索更快更准

不做这一步也不会坏，只是记忆会碎、500 条更容易满。

## 7. 管理界面

右键「她记得的事…」：

- 列出全部记忆，显示类型、时间、被用次数
- 失效的灰显并标注「已被取代 → 新内容」
- 每条可「忘记」（物理删除）或「置顶」（`uses` 不参与淘汰，永久保留）
- 底部：`整理昨天` / `合并相近` / `打开记忆文件` / `归档` 视图
- `profile.md` 提供「编辑画像」直接打开文本编辑器

隐私前提：这些都能看见、能改、能删。

## 8. 增长曲线（为什么后期不会变慢）

| 时间 | 活跃记忆 | 归档 | 磁盘 | 单次输入 |
|---|---|---|---|---|
| 1 周 | ≤40 条 | 0 | <100 KB | 恒定 ≤1600 字 |
| 1 月 | ~180 条 | 0 | ~200 KB | 恒定 |
| 6 月 | 500 条 | ~200 条 | ~1 MB | 恒定 |
| 1 年 | 500 条 | ~800 条 | ~2 MB | 恒定 |

- 检索从 40 条到 500 条，本地耗时差别 <2ms
- 提取/合并都是后台，不占聊天延迟
- 唯一会随规模增长的是磁盘，量级在 MB

## 9. 失败与降级

| 情况 | 行为 |
|---|---|
| 没填 Key | 只读不写：仍能用已有记忆，停止提取 |
| 提取接口失败 | 不改 `mem_done`，下次启动重试 |
| 提取输出乱格式 | 跳过无法解析的行，记录日志 |
| 记忆文件损坏 | 逐行容错，坏行跳过；不整体清空 |
| 检索无命中 | 不加记忆块，正常聊天 |
| 归档满了 | 归档只增不删；用户可在界面手动清 |

## 10. 实施顺序与验收

1. **存储层**：读写 `memories.jsonl`、`archive.jsonl`、`profile.md`
   验收：手改文件后重启能正确加载
2. **检索层**：BM25 + 预算组装 + `prompt:` 日志
   验收：问一句带专有名词的话，日志里 `mem≥1`；无关的话 `mem=0`
3. **提取层**：每日补跑、ADD/SUPERSEDE、去重、归档
   验收：改一条事实后，旧条变 `valid=0` 且不再被检索
4. **合并层**：每周簇合并
   验收：3 条相近记忆合并后，总数减少且能回答原问题
5. **管理窗**：列表、忘记、置顶、打开文件
   验收：删除后下一次请求不再出现

## 11. 不采用及原因

| 方案 | 原因 |
|---|---|
| 写入时打重要度 | 无法预测未来价值；模型打分不稳定 |
| 每条消息即时抽取 | 每条请求翻倍，延迟和费用都上来 |
| 向量/embedding 检索 | 需要额外接口和索引；本地 BM25 对 500 条够用 |
| 知识图谱（Graphiti/HippoRAG） | 单人陪伴过度设计，C# 无现成图库 |
| 物理删除旧记忆 | 丢失“以前是…”的上下文；改归档 + 失效 |
| 让模型每轮自编辑记忆 | MemGPT 式工具调用，延迟不可接受 |
